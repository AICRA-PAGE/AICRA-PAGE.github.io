## 프로젝트 배경

AI 에이전트의 행동은 전통적인 침해사고보다 더 잘게 쪼개지고 빠르게 반복될 수 있습니다. 단일 프로세스나 IP 주소만 추적해서는 목표, 도구 호출, 샌드박스 이동과 자격증명 사용을 하나의 사건으로 재구성하기 어렵습니다.

이 프로젝트는 AI가 공격에 사용된 경우뿐 아니라, 정상적인 모델 평가가 예상 밖의 운영 환경 접근으로 이어진 경우까지 포함합니다. 핵심은 “모델이 왜 그랬는가”를 추측하는 대신, 어떤 경계가 열렸고 어떤 실행이 승인되었으며 어떤 증거가 남았는지를 재현하는 것입니다.

## 초기 통제 가설

1. 모델 평가 환경은 인터넷, 데이터 레지스트리와 운영 자격증명에서 기본적으로 분리해야 합니다.
2. 도구 호출에는 실행 주체·목적·모델·프롬프트·승인·결과를 잇는 불변 ID가 필요합니다.
3. 자격증명은 작업 단위의 짧은 수명과 최소 권한으로 발급되어야 합니다.
4. 사고 분석용 모델은 민감한 명령·자격증명·C2 흔적을 외부로 보내지 않는 대체 경로가 필요합니다.
